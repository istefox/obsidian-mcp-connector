## 2. Protocol: MCP specification vs this server

### 2.1 Revisions

Current revision is `2026-07-28` (https://modelcontextprotocol.io/specification/versioning). The draft changelog is empty, so no later revision is in public preparation. The SEP index lists 42 SEPs, all Final; the in-review PRs most relevant here are SEP-2127 Server Cards (`.well-known/ai-catalog.json`), SEP-2792 per-request user language, SEP-2145 standardized `tools/call` failure reporting, and the draft SEP-3118 app-rendered elicitations for MCP Apps.

The project serves both the `2026-07-28` and the pre-2026 era from one endpoint (ADR-0016), and the conformance harness reports 26/28 with a hand-maintained four-entry baseline. That part is in good shape and nothing below asks to change it.

What the SDK releases change for this server (read from the GitHub releases):

- **server 2.1.0**: a missing `MCP-Protocol-Version` on a modern POST is now 400 / `-32020`; tests that hand-build modern requests must set it. Default body cap 4 MiB, but the project passes `parsedBody`, so its own `readBodyWithCap` stays authoritative. New batch bound of 100 messages.
- **server 2.2.0**: `subscriptions/listen` ends right after the ack when no notification type is honoured.
- **server 2.3.0 / node 2.1.1**: "one server per request" is now enforced (`Server.connect()` rejects a second connect). The project already builds a fresh `McpServer` per request on both eras (`buildMcpServer(tokenId)`, ADR-0016 § 4), so it is already in the required shape. `registerTool` no longer converts schemas eagerly, which lowers the per-request registration cost this audit flags in § 7. `tasks/get` and `tasks/cancel` are served on 2026-07-28.
- **ext-apps 2.0.0**: peer moves from `@modelcontextprotocol/sdk@^1` to `@modelcontextprotocol/client@^2`; the wire protocol is unchanged. This removes the "second SDK line" ADR-0018 listed as a negative, and with it the reason for the `fast-uri`, `ip-address`, `path-to-regexp` and `qs` overrides (§ 6). Not verified: that the `./app-with-deps` entry still exists in 2.0.3 (the D10 drift test would catch it at `gen:mcp-app`).
- **Documentation risk**: ADR-0016/0017/0018 cite hashed SDK file names (`mcp-DXXb3Vv3.mjs:1550`, `src-CX2iR2pK.mjs:5101`). They change on every SDK build; after the upgrade, re-verify `REQUIRED_CLIENT_CAPABILITIES_BY_METHOD = {}` (it justifies two baseline entries) and the `listChanged ?? true` rewrite.

### 2.4 MCP Apps and issue #538

The ext-apps spec is Stable (2026-01-26). When `_meta.ui.csp` is absent the host must apply `default-src 'none'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; media-src 'self' data:; connect-src 'none'` (https://github.com/modelcontextprotocol/ext-apps, `specification/2026-01-26/apps.mdx`). `blob:` appears nowhere in the stable or draft spec, so the current `import()` of a Blob URL in `assets/mcp-apps/searchResults.html:410-416` is outside any conformant CSP. It works in Claude Desktop only because the claude.ai proxy serves its own fixed CSP including `blob:` and ignores `_meta.ui.csp` (ext-apps issue #761, open). pi-mcp-adapter applies the spec default and is therefore the correct behaviour. PR #539 (inline the bundle in one `<script type="module">`) is the only spec-conformant approach; it is blocked because the drift test depends on the Bun minifier version (1.3.x passes drift, fails five broker tests; 1.4.2 the reverse). The way out proposed in the PR thread, make the drift test independent of the minifier output (hash the unminified input, or compare after a normalizing parse), is the right one and should be done on `main` first so the external PR can rebase.

Also relevant: the flat `_meta["ui/resourceUri"]` key is `@deprecated` in the spec and "will be removed before GA"; the project writes both forms (`mcp-apps/index.ts:63-68`), which is correct today. Keep `AppOptions.allowUnsafeEval` at `false`. Hosts that render apps today: Claude web, Claude Desktop (local stdio servers included, so the `.mcpb` path reaches the view), ChatGPT, VS Code Copilot, Goose, Postman, Cursor and others; Claude Code hides `ui://` resources; Codex advertises the extension behind a feature flag with no documented rendering surface.

### 2.5 Registry

The MCP Registry is in preview and requires either a public remote URL or a package; a `127.0.0.1` server inside Obsidian cannot be published as a remote. The only route would be `registryType: "mcpb"` pointing at the GitHub release bundle, but that bundle is a shim that needs the plugin running. No action.

Consequences for this plugin:

- **Codex ignores `tools/list_changed`**, so an `activate_tool` promotion never reaches a Codex session's catalog. A token used by Codex should default to a non-adaptive profile, or the Codex installer should say so. Today a never-seen token id defaults to `adaptive` (2.5.0).
- **Codex has no prompts.** The Prompts feature is invisible to the one client the discovery broker was built for; worth one README line.
- **Claude Code's own tool search** overlaps the plugin's adaptive loading: the three meta-tools should carry `_meta["anthropic/alwaysLoad"]: true` (via the existing `ToolRegistryClass.setMeta()`, `toolRegistry.ts:505`) or Claude Code may defer `tool_catalog` itself. `_meta["anthropic/maxResultSizeChars"]` on `get_vault_file` and the two search tools lets Claude Code keep large results inline.
- **`SERVER_INSTRUCTIONS` is ~627 chars**: under Claude Code's 2,048 cap, over Codex's 512-char "self-contained" guidance. Reorder so the three conventions (vault-relative paths, 0-indexed lines, `errorCode`) fit the first 512 characters.

### 3.2 Config drift per client

**Claude Code.** README lines 353-367 tell the user to paste into `~/.claude.json` (project) or `~/.claude/settings.json` (global). Neither is the documented path today: project scope is `.mcp.json` at the repo root, `~/.claude.json` is the local/user store the docs say not to edit, and `settings.json` has no `mcpServers` key in the settings reference. Replace with `claude mcp add --transport http --scope user obsidian-mcp-connector http://127.0.0.1:27200/mcp --header "Authorization: Bearer TOKEN"` and a `.mcp.json` variant using `${OBSIDIAN_MCP_TOKEN}` expansion so a team can commit the file without the secret. Optional per-server `timeout` and `alwaysLoad` are not emitted. `claude mcp add-from-claude-desktop` imports the legacy `npx mcp-remote` stdio entry, not the `.mcpb`.

**Claude Desktop / MCPB.** `manifest_version: "0.3"`, `server.type: "node"` and the `${__dirname}` substitution in `mcpbGenerator.ts:32-106` are all still valid (0.4 exists only for the `uv` type). Missing optional metadata the host displays: `compatibility.platforms: ["darwin","win32"]`, `repository`, `homepage`, `license`, `keywords`, `tools_generated: true` and `prompts_generated: true` (the lists are dynamic and per token). `mcpb validate` left CI with ADR-0013's 2.0.2 addendum and `mcpb-smoke.ts` does not run the schema validator; re-adding it against 2.1.2 is cheap. The `npx mcp-remote` fallback in `claudeDesktop.ts` and README line 312 is doubly obsolete: ADR-0013 measured that mcp-remote opens a GET SSE stream this server answers 405, and the Desktop docs now route any remote server through Settings → Connectors over HTTPS. Only the `.mcpb` and the Windows Python bridge remain valid Desktop paths. Note the directory no longer accepts MCPB submissions, so the `.mcpb` stays a sideload.

**Codex.** `codex mcp add` has no `--header` flag, so the snippet/installer approach is right. The snippet (`url`, `http_headers`, `enabled`, `required`) is valid. The key sets in `codexConfig.ts:546-579` ("verified live 2026-09-13") have drifted: `env_vars`, `experimental_environment` (stdio-only) and `http_headers_helper` (conflicts with the static header) belong in `DISCARDED_KEYS`; `startup_readiness` and `tool_input_schema_max_bytes` belong in `PRESERVED_KEYS`. Today an entry carrying any of them is refused with "copy the snippet". Not leveraged: `default_tools_approval_mode = "writes"` (free win on top of the existing `readOnlyHint`, as an opt-in checkbox), `startup_timeout_sec` above the 10 s default for the broker cold start, `tool_timeout_sec` above 60 s for indexing-class tools.

**Cline.** Named in `package.json`'s description, grouped in the README under the generic `type: "streamable-http"` payload. Cline's docs accept `"type": "streamableHttp"` or `"sse"`; `generators.ts:17-19` already acknowledges the spelling in a comment but emits the other. Emit `streamableHttp` for Cline or add a per-client toggle.

## 4. Tool surface: consistency and safety

Paths below are relative to `packages/obsidian-plugin/src/features/mcp-tools/`.

### 4.1 Consistency findings

1. **Path parameter has three names.** `path` in 30+ tools; `filename` in `tools/showFileInObsidian.ts:8` and `tools/getVaultFilePartial.ts:21`; `templatePath`/`targetPath`, `from`/`to`. Output uses `filename` (`searchVaultSimple.ts:58`), `filePath` (`semantic-search/index.ts:48`) and `path`.
2. **snake_case vs camelCase.** `dry_run`, `exclude_folders`, `include_types` against `includeUnresolved`, `maxMatchesPerFile`, `createTargetIfMissing`; output `line_number`/`total_broken_links` against `totalLinks`/`nodeCount`.
3. **Three error envelopes, three code casings.** Flat text (`getVaultFile.ts:264-275`, `patchVaultFile.ts:70-72`, `deleteVaultFile.ts:27`, `executeObsidianCommand.ts:25-29`); JSON with snake codes but divergent names for the same event (`file_not_found` in `getNoteProperty.ts:38-43`, `canvas_not_found` in `getCanvas.ts:33`, `template_not_found` in `executeTemplate.ts:105`); kebab in `renameHeading.ts:119,210,265,289` (`file-not-found`, `ambiguous-heading`) against `ambiguous_heading` in `appendToPeriodicNote.ts:154`. `errorJson` exists in `services/responseBuilders.ts:30` next to four local `errorPayload` copies (`executeDataviewQuery.ts:243`, `executeTemplate.ts:312`, `appendToPeriodicNote.ts:198`, `renameHeading.ts:49`).
4. **Overlap.** `search_vault` in dataview mode is a pure delegate to `execute_dataview_query` (`searchVault.ts:66`), and the former is in `CORE_SET` while the latter is not. `patch_*_file targetType=frontmatter` and `set_note_property` both go through `processFrontMatter`.
5. **Limits and pagination.** README says "default 200, clamped to 1000" for list and scan tools; actual: `search_vault_simple` 50 no clamp, `search_vault_smart` 10 no clamp, `list_property_values` 500 no clamp (`listPropertyValues.ts:32`), `get_recent_files` 1-100, `list_bookmarks`/`get_canvas`/`execute_dataview_query` no limit. No tool has `offset` or a cursor. Truncation shape differs (`{truncated, total}` vs `totalX` + optional `truncated` vs always-present boolean).
6. **`structuredContent` is patchy.** 8 tools emit it via `successJson`; `delete_note_property` does, its sibling `set_note_property` does not (`setNoteProperty.ts:126`).
7. **Boolean as string.** `createFile: '"true"|"false"'` (`executeTemplate.ts:43`) is the last residue of the pre-`coerceBooleanParams` workaround (`toolRegistry.ts:737`).
8. **Undocumented parameters.** `add_canvas_node` and `connect_canvas_nodes` have parameters without `.describe` (`addCanvasNode.ts:19-29`, `connectCanvasNodes.ts:15-21`); `connect_canvas_nodes` does not expose `fromEnd`/`toEnd`.
9. **Hard-coded English exclusion defaults** `["templates","attachments","_archive"]` in `findBrokenLinks.ts:27` and `findOrphanedNotes.ts:23`, separate from the vault-wide hidden-folders policy; `isUserIgnored` applied by `get_recent_files` and `get_vault_overview` but not by `list_vault_files`, `search_vault_simple`, `list_tags`.
10. **Enum drift.** `format: "markdown"|"json"` (`getActiveFile.ts:14`) vs `"text"|"json"` (`getVaultFile.ts:84`, `getVaultFiles.ts:15`).
11. **Periodic siblings drift.** `get_or_create_daily_note` has `heading` and returns `uri`; `get_or_create_periodic_note` has neither (`getOrCreatePeriodicNote.ts:13-20,121`).
12. **Line indexing is mixed.** 1-based `line_number` in `get_note_outline`, `find_broken_links`, `search_and_replace`; 0-based `line` in `search_vault_simple`, `search_vault_smart` and `startLine`/`endLine` in `get_vault_file_partial`. An agent that feeds an outline line into `mode: "lines"` is off by one.
13. **`rename_heading`** claims "dry-run plan first" (`renameHeading.ts:33`) but exposes no `dry_run`.

## 7. Performance

Static analysis; no latency was measured. Ranked by impact × effort.

1. **`data.json` is read and parsed three to four times per `tools/call`.** `httpServer.ts:75` resolves tokens through `readSlice("mcpTransport")` on every request before auth; `mcpServer.ts:287-291` reads `toolLoading` for the policy; `pathPolicy.refresh()` reads `mcpTools` on `tools/call` and `prompts/*`. `SettingsStore.readSlice` (`shared/settingsStore.ts:141`) calls `plugin.loadData()` each time. Proposal: an in-memory cache in `SettingsStore` invalidated on every write through the store. Constraint: four Svelte components write through `plugin.saveData` directly (`CommandPermissionsSettings.svelte:166`, `ToolToggleSettings.svelte:64`, `AccessControlSection.svelte:396,439`). They all hold `globalSettingsMutex`, so there is no lost-update bug today, but a read cache would need an invalidation hook they can call, or they should move to the store. Effort M, highest payoff.
2. **`toolNameOf` is recomputed per request** (`toolRegistry.ts:716-727`): `listAll()` runs `schema.get("name").toJsonSchema().const` for each of ~52 tools on every `tools/list`, `tools/call` and `resolveScope`, while `entries()` is already memoized (`entriesCache`, lines 662-687). Store the name in the entry at registration. Effort S.
3. **`coerceBooleanParams`** (`toolRegistry.ts:737-773`) runs `.get("arguments").exclude("undefined")` and one ArkType `.get(key)` per argument key per dispatch. Precompute the boolean key set per tool at registration. Effort S.
4. **Two independent 2 s debounced flushes** write `data.json`: `toolLoadingManager.ts` (`RECORD_FLUSH_DELAY_MS`) and `eraCounters.ts` (`FLUSH_DELAY_MS`). Coalesce into one scheduler, or let `SettingsStore` batch writes per tick. Effort S, halves disk writes under sustained traffic.
5. **Startup**: `setup.ts` performs five to six `data.json` round trips (`ensureTokenStore`, `ensureEverCalledTracking`, `readSlice`, `pathPolicy.refresh`, `livePort` update) before the server listens; `productionWiring.ts` adds `migrateV1FlatStore`, `probeAndWipeStaleStores` (3 providers) and `detectNonAsciiRatio` (up to 50 `cachedRead`). Collapse into one `loadData` + one `saveData`, defer `detectNonAsciiRatio` behind `startIndexerIfNeeded`, gate the Smart Connections poll on the configured provider. Effort S-M.
6. **Bundle**: see § 6 (domino stub, rxjs removal, zod dedupe). `ort.all.min.js` includes WebGPU + WASM + WebNN; `onnxEnv.ts` uses only wasm/webgpu, so `onnxruntime-web/webgpu` instead of `/all` may save a slice (not measured). `searchResultsAppSource.ts` embeds 345 KB of HTML/JS as a string; minify at generation time.
7. **`guardedApp.ts` `filterLinkMap`** rebuilds the filtered `resolvedLinks`/`unresolvedLinks` map on every access, O(links in vault). Cache per policy revision, invalidate on `metadataCache.on("resolved")`. Effort S.
8. **Semantic search**: `rebuildAll` is sequential, embedding runs on the main thread (no Worker), `EMBED_BATCH_SIZE = 8`, `chunker.ts hashChunk` uses `crypto.subtle.digest` (one async round trip per chunk) where a sync FNV/xxhash suffices for dedup, and the native provider does a linear scan with an ordered top-k insert. Already good: segmented `Float32Array` store, `contentHash` reuse, LRU 32, idle unload. Worker offload is the one change users would feel (no UI jank during indexing). Effort L.
9. **`patchHelpers.ts`** recomputes `computeFenceOpenState(lines)` in three places and re-splits `content` in `findBlockReferenceInContent` when `lines` already exists. Linear, cleanup only.
